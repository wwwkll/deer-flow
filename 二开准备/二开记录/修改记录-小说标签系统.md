## 三、技术实现

### 3.1 数据存储
- **存储位置**：SQLite 数据库 `{DEER_FLOW_HOME}/global_variables.db`
- **变量名**：`novel_toc`（小说目录）
- **存储内容**：完整的容器路径（如 `/mnt/shared-data/novels/book/小说A`）
- **UI 显示**：提取路径最后一段（如"小说A"）

### 3.2 目录结构
```
backend/.deer-flow/shared-data/
└── novels/
    └── book/
        ├── 小说A/
        ├── 小说B/
        └── 小说C/
```

### 3.3 API 设计

**GET /api/novel-tags/**
- 功能：获取所有可用的小说目录列表
- 扫描路径：`sandbox.mounts` 配置下的 host_path
- 扫描规则：查找名为 `book` 或 `books` 的目录（最多3级深度）
- 返回值：完整容器路径列表
- 缓存：5分钟 TTL

**响应示例**：
```json
{
  "tags": [
    "/mnt/shared-data/novels/book/小说A",
    "/mnt/shared-data/novels/book/小说B",
    "/mnt/shared-data/novels/book/小说C"
  ]
}
```

## 六、当前问题

### 6.1 问题1：选择器显示"没有找到小说"

**现象**：
- 用户已创建 `shared-data/novels/book/小说A` 等目录
- 前端请求 `/api/novel-tags/` 返回 `{"tags": []}`

**可能原因**：
1. 配置加载问题 - `get_app_config()` 可能未正确加载 mounts
2. 路径解析问题 - 相对路径转绝对路径可能出错
3. Windows 路径分隔符 - `\` 未正确转为 `/`
4. 缓存问题 - 旧的空缓存未过期

**已采取的排查措施**：
1. 添加了详细的调试日志（`logger.warning` 级别）
2. 修复了路径分隔符问题（`replace("\\", "/")`）
3. 处理了 container_path 末尾斜杠

**待验证**：
- 重启服务后查看后端日志中的 `[DEBUG]` 信息

### 6.2 已知限制
- 缓存 5 分钟后才会刷新新添加的小说目录
- 不支持多级分类（扁平标签）
- 不支持搜索和筛选

## 八、配置说明

### 8.1 config.yaml 配置

```yaml
sandbox:
  mounts:
    - host_path: backend/.deer-flow/shared-data
      container_path: /mnt/shared-data
      read_only: false
```

**说明**：
- `host_path`：主机路径，支持相对路径（相对于项目根目录）
- `container_path`：容器内路径，用于生成 novel_toc 值
- 小说目录需要放在此路径下的 `book` 或 `books` 文件夹中

### 8.2 目录创建规范
```
shared-data/
└── novels/                    # 可选的中间目录
    └── book/                  # 必须叫 book 或 books
        ├── 小说A/
        ├── 小说B/
        └── 小说C/
```
