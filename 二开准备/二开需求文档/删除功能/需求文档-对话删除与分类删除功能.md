# 需求文档：对话删除增强与分类删除功能

**日期**: 2026-05-16
**状态**: 需求分析 + 技术方案

---

## 一、需求概述

### 1.1 背景

当前 DeerFlow 已具备基础的对话删除功能，但存在以下问题：
1. **对话删除不彻底**：删除对话时仅清理了线程目录、Store 记录和 Checkpoint，未清理该对话在全局变量数据库中的对话级变量，导致数据残留。
2. **分类管理缺失**：前端对话列表已按 `novel_toc` 分组展示（即"分类"），但缺乏对分类的批量操作能力，无法清空分类下所有对话或删除整个小说项目。

### 1.2 需求列表

| 需求编号 | 需求名称 | 优先级 | 说明 |
|---------|---------|--------|------|
| REQ-001 | 对话删除增强 | 高 | 删除对话时同步删除该对话的所有对话级全局变量 |
| REQ-002 | 清空分类对话 | 高 | 清空指定分类下的所有对话 |
| REQ-003 | 删除分类（小说） | 高 | 删除指定分类，包括清空所有对话 + 删除关联的小说文件 |

---

## 二、需求详细说明

### 2.1 REQ-001：对话删除增强

#### 2.1.1 现状

当前删除对话的接口 `DELETE /api/threads/{thread_id}` 执行以下操作：
1. 删除本地线程目录（`path_manager.delete_thread_dir()`）
2. 从 Store 删除线程记录（`store.adelete()`）
3. 从 Checkpointer 删除 Checkpoint（`checkpointer.adelete_thread()`）

**缺失**：未删除 `global_variables` 表中该对话的所有记录。

#### 2.1.2 需求描述

在现有删除逻辑基础上，增加第 4 步：
4. **删除该对话的所有对话级全局变量**

#### 2.1.3 业务规则

- **清理范围**：仅删除 `thread_id = {thread_id}` 的所有记录
- **不清理项目级变量**：`thread_id IS NULL` 的记录不受影响
- **不影响其他对话**：其他对话的变量完全隔离，不受影响
- **幂等性**：如果该对话没有对话级变量，此步骤静默通过
- **最佳 effort**：此步骤失败不应影响主删除流程的返回结果，但应记录日志

#### 2.1.4 接口影响

| 接口 | 方法 | 变更 |
|------|------|------|
| `/api/threads/{thread_id}` | DELETE | 增加全局变量清理逻辑 |

---

### 2.2 REQ-002：清空分类下所有对话

#### 2.2.1 需求描述

为前端对话列表中的每个分类（小说分组）提供"清空对话"功能，一键删除该分类下的所有对话。

#### 2.2.2 业务规则

- **操作对象**：指定分类（由 `novel_toc` 路径最后一段确定分类名）
- **操作内容**：
  1. 查询该分类下所有对话的 `thread_id`
  2. 为每个对话执行完整的删除操作（含 REQ-001 的全局变量清理）
- **不删除小说文件**：仅删除对话，保留 `novel_toc` 指向的目录及文件
- **未分类处理**："未分类"组（`__undefined__`）不提供此功能

#### 2.2.3 前端交互

- 在分类标题行（`RecentChatList` 中的分组标题）增加操作菜单
- 提供"清空对话"选项
- 操作前需二次确认（Confirm Dialog）

#### 2.2.4 后端接口

**新增接口**：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/categories/{category_name}/clear` | POST | 清空指定分类下的所有对话 |

**请求参数**：
- `category_name` (path): 分类名称（即 `novel_toc` 路径最后一段）

**响应**：
```json
{
  "success": true,
  "message": "Cleared 5 threads from category '小说A'",
  "deleted_count": 5
}
```

### 2.3 REQ-003：删除分类（小说）

#### 2.3.1 需求描述

为前端对话列表中的每个分类提供"删除小说"功能，彻底删除该分类及关联的所有数据。

#### 2.3.2 业务规则

- **操作对象**：指定分类（由 `novel_toc` 路径最后一段确定分类名）
- **操作内容**：
  1. 查询该分类下所有对话的 `thread_id`
  2. 为每个对话执行完整的删除操作（含 REQ-001 的全局变量清理）
  3. 获取该分类关联的小说目录路径（通过任意一个对话的 `novel_toc` 变量）
  4. 删除该小说目录及目录下所有文件（文件系统操作）
- **未分类处理**："未分类"组（`__undefined__`）不提供此功能
- **危险操作**：需二次确认，提示用户此操作不可恢复

#### 2.3.3 前端交互

- 在分类标题行增加操作菜单
- 提供"删除小说"选项（红色危险样式）
- 操作前需二次确认，显示警告信息：
  > "此操作将删除分类「小说A」下的所有对话，并永久删除关联的小说文件。此操作不可恢复，是否继续？"

#### 2.3.4 后端接口

**新增接口**：

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/categories/{category_name}` | DELETE | 删除指定分类及关联文件 |

**请求参数**：
- `category_name` (path): 分类名称

**响应**：
```json
{
  "success": true,
  "message": "Deleted category '小说A' with 5 threads and removed directory '/mnt/shared-data/book/小说A'",
  "deleted_threads": 5,
  "novel_path": "/mnt/shared-data/book/小说A"
}
```

def delete_all_by_thread(self, thread_id: str) -> int:
    """Delete all variables for a specific thread."""
    try:
        with self._get_connection() as conn:
            cursor = conn.cursor()
            cursor.execute(
                """
                DELETE FROM global_variables
                WHERE thread_id = ?
            """,
                (thread_id,),
            )
            deleted = cursor.rowcount

            return deleted

#### 3.2.2 修改对话删除接口

**文件**: `backend/app/gateway/routers/threads.py`

在 `delete_thread_data` 函数中增加全局变量清理步骤：

```python
from deerflow.global_variables.storage import get_storage

@router.delete("/{thread_id}", response_model=ThreadDeleteResponse)
async def delete_thread_data(thread_id: str, request: Request) -> ThreadDeleteResponse:
    """Delete local persisted filesystem data for a thread."""
    # 1. Clean local filesystem
    response = _delete_thread_data(thread_id)

    # 2. Remove from Store (best-effort)
    store = get_store(request)
    if store is not None:
        try:
            await store.adelete(THREADS_NS, thread_id)
        except Exception:
            logger.debug("Could not delete store record for thread %s (not critical)", thread_id)

    # 3. Remove checkpoints (best-effort)
    checkpointer = getattr(request.app.state, "checkpointer", None)
    if checkpointer is not None:
        try:
            if hasattr(checkpointer, "adelete_thread"):
                await checkpointer.adelete_thread(thread_id)
        except Exception:
            logger.debug("Could not delete checkpoints for thread %s (not critical)", thread_id)

    # 4. Remove global variables for this thread (best-effort)
    try:
        deleted_count = get_storage().delete_all_by_thread(thread_id)
        if deleted_count > 0:
            logger.info("Deleted %d global variables for thread %s", deleted_count, thread_id)
    except Exception:
        logger.debug("Could not delete global variables for thread %s (not critical)", thread_id)

    return response
```

#### 3.2.3 新增分类管理路由

**新增文件**: `backend/app/gateway/routers/categories.py`

```python
"""Category management endpoints for novel-based thread grouping."""

import logging
import shutil
from typing import Any

from fastapi import APIRouter, HTTPException
from pydantic import BaseModel, Field

from deerflow.global_variables.storage import get_storage
from deerflow.config.paths import get_paths

logger = logging.getLogger(__name__)
router = APIRouter(prefix="/api/categories", tags=["categories"])


class CategoryClearResponse(BaseModel):
    """Response model for clearing category threads."""
    success: bool
    message: str
    deleted_count: int


class CategoryDeleteResponse(BaseModel):
    """Response model for deleting a category."""
    success: bool
    message: str
    deleted_threads: int
    novel_path: str | None = None


def _get_threads_by_category(category_name: str) -> list[str]:
    """Get all thread IDs that belong to a category."""
    novel_tocs = get_storage().load_novel_tocs()
    thread_ids = []
    for thread_id, toc_path in novel_tocs.items():
        segments = toc_path.split("/")
        if segments and segments[-1] == category_name:
            thread_ids.append(thread_id)
    return thread_ids


def _get_novel_path_by_category(category_name: str) -> str | None:
    """Get the novel directory path for a category."""
    novel_tocs = get_storage().load_novel_tocs()
    for toc_path in novel_tocs.values():
        segments = toc_path.split("/")
        if segments and segments[-1] == category_name:
            return toc_path
    return None


@router.post("/{category_name}/clear", response_model=CategoryClearResponse)
async def clear_category_threads(category_name: str) -> CategoryClearResponse:
    """Clear all threads in a category.

    Deletes all threads that belong to the specified category,
    but preserves the novel directory and files.
    """
    if category_name == "__undefined__":
        raise HTTPException(status_code=400, detail="Cannot clear undefined category")

    thread_ids = _get_threads_by_category(category_name)
    if not thread_ids:
        return CategoryClearResponse(
            success=True,
            message=f"No threads found in category '{category_name}'",
            deleted_count=0,
        )

    deleted_count = 0
    for thread_id in thread_ids:
        try:
            # Reuse existing thread deletion logic
            # Note: In actual implementation, we should call the thread deletion API
            # or extract the deletion logic into a shared function
            deleted_count += 1
        except Exception as e:
            logger.error("Failed to delete thread %s: %s", thread_id, e)

    return CategoryClearResponse(
        success=True,
        message=f"Cleared {deleted_count} threads from category '{category_name}'",
        deleted_count=deleted_count,
    )


@router.delete("/{category_name}", response_model=CategoryDeleteResponse)
async def delete_category(category_name: str) -> CategoryDeleteResponse:
    """Delete a category and its associated novel directory.

    Deletes all threads in the category and removes the novel directory.
    This operation is irreversible.
    """
    if category_name == "__undefined__":
        raise HTTPException(status_code=400, detail="Cannot delete undefined category")

    # Get novel path before deleting threads
    novel_path = _get_novel_path_by_category(category_name)

    # Clear all threads in the category
    thread_ids = _get_threads_by_category(category_name)
    deleted_threads = 0
    for thread_id in thread_ids:
        try:
            # Reuse existing thread deletion logic
            deleted_threads += 1
        except Exception as e:
            logger.error("Failed to delete thread %s: %s", thread_id, e)

    # Delete novel directory
    deleted_path = None
    if novel_path:
        try:
            paths = get_paths()
            # Convert container path to host path if needed
            # For now, we assume the path is directly accessible
            import os
            if os.path.exists(novel_path):
                shutil.rmtree(novel_path)
                deleted_path = novel_path
                logger.info("Deleted novel directory: %s", novel_path)
        except Exception as e:
            logger.error("Failed to delete novel directory %s: %s", novel_path, e)

    return CategoryDeleteResponse(
        success=True,
        message=f"Deleted category '{category_name}' with {deleted_threads} threads",
        deleted_threads=deleted_threads,
        novel_path=deleted_path,
    )
```

import { useMutation, useQueryClient } from "@tanstack/react-query";
import { getBackendBaseURL } from "@/core/api";

export function useClearCategory() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: async (categoryName: string) => {
      const response = await fetch(
        `${getBackendBaseURL()}/api/categories/${encodeURIComponent(categoryName)}/clear`,
        { method: "POST" }
      );
      if (!response.ok) {
        const error = await response.json().catch(() => ({ detail: "Failed to clear category" }));
        throw new Error(error.detail ?? "Failed to clear category");
      }
      return response.json();
    },
    onSuccess() {
      void queryClient.invalidateQueries({ queryKey: ["threads", "search"] });
      void queryClient.invalidateQueries({ queryKey: ["thread-novel-toc"] });
    },
  });
}

export function useDeleteCategory() {
  const queryClient = useQueryClient();
  return useMutation({
    mutationFn: async (categoryName: string) => {
      const response = await fetch(
        `${getBackendBaseURL()}/api/categories/${encodeURIComponent(categoryName)}`,
        { method: "DELETE" }
      );
      if (!response.ok) {
        const error = await response.json().catch(() => ({ detail: "Failed to delete category" }));
        throw new Error(error.detail ?? "Failed to delete category");
      }
      return response.json();
    },
    onSuccess() {
      void queryClient.invalidateQueries({ queryKey: ["threads", "search"] });
      void queryClient.invalidateQueries({ queryKey: ["thread-novel-toc"] });
    },
  });
}

## 六、风险与注意事项

### 6.1 风险

| 风险 | 等级 | 说明 | 应对措施 |
|------|------|------|---------|
| 误删其他对话变量 | 高 | `delete_all_by_thread` 的 WHERE 条件错误 | 严格代码审查 + 单元测试 |
| 误删项目级变量 | 高 | 未正确区分 `thread_id IS NULL` | 单元测试覆盖 |
| 误删其他小说文件 | 高 | 分类匹配逻辑错误 | 路径精确匹配 + 二次确认 |
| 并发删除冲突 | 中 | 多个用户同时操作同一分类 | 事务控制 + 乐观锁 |

### 6.2 注意事项

1. **路径转换**：`novel_toc` 存储的是容器内路径，删除文件时需要转换为宿主机路径
2. **权限检查**：删除文件前需确认进程有写权限
3. **软链接处理**：如果 `novel_toc` 指向软链接，需谨慎处理
4. **日志记录**：所有删除操作需记录详细日志，便于审计
5. **备份提醒**：删除小说前可提示用户先导出/备份重要数据
