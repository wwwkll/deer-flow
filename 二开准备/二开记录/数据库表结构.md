## 一、表结构

### global_variables 表

存储项目级和对话级全局变量。

```sql
CREATE TABLE IF NOT EXISTS global_variables (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    thread_id TEXT NULL,
    key TEXT NOT NULL,
    value TEXT NOT NULL,
    description TEXT DEFAULT '',
    is_system BOOLEAN DEFAULT FALSE,
    llm_editable BOOLEAN DEFAULT TRUE,
    updated_at TEXT NOT NULL,
    updated_by TEXT NOT NULL,
    UNIQUE(thread_id, key)
);
```

### 字段说明

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 自增主键 |
| `thread_id` | TEXT | NULL | 对话ID，项目级变量为 NULL |
| `key` | TEXT | NOT NULL | 变量名（如 `workdir`、`novel_toc`） |
| `value` | TEXT | NOT NULL | 变量值 |
| `description` | TEXT | DEFAULT '' | 变量描述 |
| `is_system` | BOOLEAN | DEFAULT FALSE | 是否系统变量（系统变量不写入此表，见下方说明） |
| `llm_editable` | BOOLEAN | DEFAULT TRUE | 大模型是否可通过工具修改 |
| `updated_at` | TEXT | NOT NULL | 最后更新时间（ISO 8601 格式） |
| `updated_by` | TEXT | NOT NULL | 最后更新来源（`api`、`tool`、`system`） |

### 唯一约束

```sql
UNIQUE(thread_id, key)
```

- 项目级变量：`(NULL, key)` 唯一
- 对话级变量：`(thread_id, key)` 唯一
- 同一对话内不允许重复变量名
- 不同对话间变量完全隔离

## 二、系统变量说明

**系统变量不写入数据库表**，仅存在于内存中（`SYSTEM_VARIABLES` 常量）。

```python
# backend/packages/harness/deerflow/global_variables/storage.py
SYSTEM_VARIABLES = {
    "workdir": {
        "value": "/mnt/shared-data",
        "description": "Shared workspace directory",
        "is_system": True,
        "llm_editable": False,
        "updated_at": "system",
        "updated_by": "system",
    },
}
```

**加载时合并**：前端或 API 读取变量时，系统变量自动合并到返回列表中。

**保存时过滤**：写入数据库时自动过滤 `is_system=True` 的变量。

## 三、写入规范

### 3.1 字段隔离原则

**禁止使用 `INSERT OR REPLACE`**：该语句会完全替换整行记录，导致未指定字段被设置为 NULL 或默认值。

**使用 UPDATE + INSERT 两段式模式**：

```python
# 项目级变量写入
cursor.execute("""
    UPDATE global_variables
    SET value = ?, description = ?, llm_editable = ?, updated_at = ?, updated_by = ?
    WHERE thread_id IS NULL AND key = ?
""", (value, description, llm_editable, now, "api", key))

if cursor.rowcount == 0:
    cursor.execute("""
        INSERT INTO global_variables
        (thread_id, key, value, description, is_system, llm_editable, updated_at, updated_by)
        VALUES (?, ?, ?, ?, ?, ?, ?, ?)
    """, (None, key, value, description, False, llm_editable, now, "api"))
```

```python
# 对话级变量写入
cursor.execute("""
    UPDATE global_variables
    SET value = ?, description = ?, llm_editable = ?, updated_at = ?, updated_by = ?
    WHERE thread_id = ? AND key = ?
""", (value, description, llm_editable, now, "api", thread_id, key))

if cursor.rowcount == 0:
    cursor.execute("""
        INSERT INTO global_variables
        (thread_id, key, value, description, is_system, llm_editable, updated_at, updated_by)
        VALUES (?, ?, ?, ?, ?, ?, ?, ?)
    """, (thread_id, key, value, description, False, llm_editable, now, "api"))
```

### 3.2 设计说明

1. **UPDATE 只更新指定字段**：不会覆盖其他模块写入的字段
2. **rowcount 判断**：SQLite 不支持 `ON DUPLICATE KEY UPDATE`（MySQL 专属语法），使用 `rowcount == 0` 判断是否需要 INSERT
3. **WHERE 条件精确**：项目级用 `thread_id IS NULL AND key = ?`，对话级用 `thread_id = ? AND key = ?`
4. **性能最优**：先 UPDATE 再 INSERT，避免先查询再判断的两次数据库交互

### 3.3 为什么不用 INSERT OR REPLACE

`INSERT OR REPLACE` 的问题：

```sql
-- 错误示例：会覆盖所有字段
INSERT OR REPLACE INTO global_variables (thread_id, key, value)
VALUES (?, ?, ?)
-- 结果：description、llm_editable、updated_at、updated_by 都被设为默认值！
```

### 3.4 为什么不用 ON DUPLICATE KEY UPDATE

`ON DUPLICATE KEY UPDATE` 是 MySQL 专属语法，SQLite 不支持：

```sql
-- MySQL 语法（SQLite 不支持）
INSERT INTO global_variables (...)
VALUES (...)
ON DUPLICATE KEY UPDATE value = VALUES(value)
```

SQLite 的替代方案就是 UPDATE + INSERT 两段式模式。

### 3.5 注意事项

1. **UPDATE 语句中不要包含 `is_system` 字段**：该字段由 INSERT 时设置，UPDATE 时不需要修改，保持字段隔离
2. **INSERT 语句必须显式指定所有字段**：包括 `is_system`，防止未来新增字段时出现 NULL 值问题
3. **项目级变量的 `thread_id` 必须为 NULL**，不能用空字符串或其他值替代

## 四、索引

### 实际创建的索引

```sql
-- 由 UNIQUE(thread_id, key) 约束自动创建
CREATE INDEX IF NOT EXISTS idx_thread_id ON global_variables(thread_id);
CREATE INDEX IF NOT EXISTS idx_key ON global_variables(key);
CREATE INDEX IF NOT EXISTS idx_thread_key ON global_variables(thread_id, key);
```

**说明**：SQLite 会自动为 UNIQUE 约束创建唯一索引，查询性能已优化。

**用户授权说明**：当前表结构和索引为全局变量系统初始设计的一部分，已在用户允许范围内创建。后续未经允许不得新建数据库表、字段或索引。

## 六、全局变量数据类型与作用说明

### 6.1 数据类型总览

全局变量系统存储的所有值均为 **TEXT（文本）类型**，但在业务层面根据用途可分为以下几类数据类型：

| 数据类型 | 存储格式 | 说明 | 典型变量 |
|---------|---------|------|---------|
| **路径型** | 文件系统路径字符串 | 指向容器内的目录或文件路径 | `workdir`、`novel_toc` |
| **文本型** | 纯文本/多行文本 | 普通文本内容，用于提示词注入 | `role`、`chapter`、`style` |
| **JSON型** | JSON 格式字符串 | 结构化数据，需解析后使用 | `card`（小说名片）、`rules` |
| **布尔型** | `"true"` / `"false"` | 以字符串形式存储的布尔值 | `auto_save`、`dark_mode` |
| **数值型** | 数字字符串 | 以字符串形式存储的整数或浮点数 | `max_tokens`、`temperature` |
| **模板型** | Markdown/文本模板 | 包含 `{{变量名}}` 占位符的模板内容 | `novel_dir_structure` |
| **枚举型** | 预定义值之一 | 从有限选项中选取的值 | `status`、`priority` |

### 6.2 各数据类型详细说明

#### 6.2.1 路径型（Path）

**格式特征**：以 `/` 分隔的绝对路径或相对路径

**作用**：
- 指定工作目录、小说项目根目录等文件系统位置
- 前端文件浏览器以此路径为根目录加载文件列表
- 分类（小说分组）依据此路径的最后一段进行分组

**典型变量**：

| 变量名 | 作用域 | 示例值 | 说明 |
|--------|--------|--------|------|
| `workdir` | 项目级（系统变量） | `/mnt/shared-data` | 共享工作目录，从 `sandbox.mounts` 配置动态读取 |
| `novel_toc` | 对话级 | `/mnt/shared-data/book/小说A` | 小说项目根目录路径，决定对话所属分类 |

**注意事项**：
- 路径为容器内路径，非宿主机路径
- `novel_toc` 为对话级变量，不同对话可指向同一目录（多对一关系）
- 分类名称由 `novel_toc` 路径最后一段提取（如 `小说A`）

#### 6.2.2 文本型（Text）

**格式特征**：任意纯文本字符串，可包含多行

**作用**：
- 在 SOUL.md 或 Agent 提示词中通过 `{{变量名}}` 语法注入
- 存储角色设定、章节标题、写作风格等文本内容

**典型变量**：

| 变量名 | 作用域 | 示例值 | 说明 |
|--------|--------|--------|------|
| `role` | 对话级 | `主角：张三，性格坚毅...` | 角色设定描述 |
| `chapter` | 对话级 | `第1章 初出茅庐` | 当前章节标题 |
| `style` | 对话级 | `古风武侠，文笔流畅` | 写作风格描述 |

**注入示例**：
```markdown
# 角色设定
{{role}}

# 当前章节
{{chapter}}
```

#### 6.2.3 JSON型（JSON）

**格式特征**：符合 JSON 格式的字符串，需 `json.loads()` 解析

**作用**：
- 存储结构化数据，如小说名片、规则配置等
- 便于程序化处理和校验

**典型变量**：

| 变量名 | 作用域 | 示例值 | 说明 |
|--------|--------|--------|------|
| `card` | 对话级 | `{"title":"小说A","author":"作者","progress":30}` | 小说名片（元数据） |
| `rules` | 对话级 | `{"max_length":3000,"allow_violence":false}` | 本书规则配置 |

**使用方式**：
```python
import json

# 读取
json_str = get_storage().load("thread", thread_id)["variables"]["card"]["value"]
card_data = json.loads(json_str)

# 写入
card_data["progress"] = 50
get_storage().save({
    "variables": {"card": {"value": json.dumps(card_data, ensure_ascii=False)}}
}, "thread", thread_id)
```

#### 6.2.4 布尔型（Boolean）

**格式特征**：字符串 `"true"` 或 `"false"`

**作用**：
- 控制开关类功能的启用状态
- 需在使用时转换为 Python 布尔值

**典型变量**：

| 变量名 | 作用域 | 示例值 | 说明 |
|--------|--------|--------|------|
| `auto_save` | 项目级 | `true` | 是否自动保存 |
| `dark_mode` | 对话级 | `false` | 是否启用暗黑模式（示例） |

**转换方式**：
```python
value = get_storage().load("project")["variables"]["auto_save"]["value"]
bool_value = value.lower() == "true"
```

#### 6.2.5 数值型（Number）

**格式特征**：数字字符串，如 `"3000"`、`"0.7"`

**作用**：
- 存储数值配置，如最大 token 数、温度参数等
- 需在使用时转换为 int 或 float

**典型变量**：

| 变量名 | 作用域 | 示例值 | 说明 |
|--------|--------|--------|------|
| `max_tokens` | 项目级 | `3000` | 单次生成最大 token 数 |
| `temperature` | 对话级 | `0.7` | 生成温度参数 |

**转换方式**：
```python
value = get_storage().load("project")["variables"]["max_tokens"]["value"]
num_value = int(value)  # 或 float(value)
```

#### 6.2.6 模板型（Template）

**格式特征**：包含占位符的文本模板，占位符格式为 `{{变量名}}`

**作用**：
- 提供可复用的结构化模板内容
- 系统变量 `novel_dir_structure` 即为模板型，用于指导小说目录创建

**典型变量**：

| 变量名 | 作用域 | 说明 |
|--------|--------|------|
| `novel_dir_structure` | 项目级（系统变量） | 小说项目目录结构模板，包含各文件夹和文件的说明 |

**使用方式**：
模板型变量通常不直接注入提示词，而是作为参考文档供 Agent 读取和处理。

#### 6.2.7 枚举型（Enum）

**格式特征**：预定义的字符串值之一

**作用**：
- 限制变量的取值范围，保证数据一致性
- 常用于状态、优先级等字段

**典型变量**：

| 变量名 | 作用域 | 可选值 | 说明 |
|--------|--------|--------|------|
| `status` | 对话级 | `draft`、`reviewing`、`published` | 小说状态 |
| `priority` | 对话级 | `low`、`medium`、`high` | 优先级 |

### 6.3 系统变量 vs 用户变量

| 对比项 | 系统变量 | 用户变量 |
|--------|---------|---------|
| `is_system` | `True` | `False` |
| 存储位置 | 内存常量 + 数据库同步 | 仅数据库 |
| 可编辑性 | `llm_editable=False`（不可编辑） | `llm_editable` 可配置 |
| 修改权限 | 仅系统内部修改 | API / 工具 / 前端均可修改 |
| 典型代表 | `workdir`、`novel_dir_structure` | `novel_toc`、`role`、`chapter` |

**系统变量列表**：

| 变量名 | 数据类型 | 作用 | 动态性 |
|--------|---------|------|--------|
| `workdir` | 路径型 | 共享工作目录 | 动态（从配置读取） |
| `novel_dir_structure` | 模板型 | 小说目录结构模板 | 静态 |

### 6.4 变量作用域说明

| 作用域 | `thread_id` | 可见性 | 使用场景 |
|--------|------------|--------|---------|
| **项目级** | `NULL` | 所有对话共享 | 全局配置、默认参数 |
| **对话级** | 具体对话ID | 仅当前对话可见 | 对话专属状态、小说绑定 |

**合并规则**：对话级变量覆盖项目级变量（同名时）。

```python
# 获取合并后的变量（对话级优先）
from deerflow.global_variables.prompt_injector import get_merged_variables
merged = get_merged_variables(thread_id="thread_123")
```

## 七、数据清理

### 7.1 对话删除时清理

```sql
DELETE FROM global_variables
WHERE thread_id = ?
```

调用时机：删除对话时，自动清理该对话的所有对话级变量。

**清理范围**：
- 仅删除 `thread_id = ?` 的所有记录
- 不涉及项目级变量（`thread_id IS NULL`）
- 不涉及其他对话的变量

### 7.2 分类（小说）删除时清理

```sql
-- 步骤1：获取分类下所有对话的 thread_id
SELECT thread_id, value FROM global_variables
WHERE key = 'novel_toc' AND value LIKE ?

-- 步骤2：删除这些对话的所有对话级变量
DELETE FROM global_variables
WHERE thread_id IN (...)

-- 步骤3：删除分类关联的小说文件（通过文件系统操作）
-- 路径从 novel_toc 变量值获取
```

调用时机：删除分类（小说）时，自动清理该分类下所有对话的变量及关联文件。

### 9.3 并发优化：WAL 模式 + busy_timeout

**日期**: 2026-05-05

**问题**: 多 Agent 并发写入时，SQLite 默认 DELETE 模式会锁整个数据库文件，导致 `database is locked` 错误，工作流失败。

**解决方案**: 启用 SQLite WAL (Write-Ahead Logging) 模式 + busy_timeout 参数。

**改动位置**:
1. `backend/packages/harness/deerflow/runtime/store/_sqlite_utils.py` — `resolve_sqlite_conn_str()` 函数
2. `backend/packages/harness/deerflow/global_variables/storage.py` — `_get_connection()` 方法

**连接字符串格式**:
```
file:/path/to/database.db?journal_mode=WAL&busy_timeout=30000
```

**参数说明**:

| 参数 | 值 | 说明 |
|------|------|------|
| `journal_mode` | `WAL` | 预写式日志模式，允许多个读取并发 + 一个写入 |
| `busy_timeout` | `30000` | 等待锁释放的超时时间（毫秒），默认 0 会立即报错 |

**WAL 模式优势**:
- 允许多个读取连接并发（读取不再锁整个文件）
- 写入时使用 `-wal` 日志文件，减少主文件锁竞争
- 崩溃恢复更安全，不会丢失数据

**busy_timeout 优势**:
- 等待 30 秒而不是立即报错
- 给其他线程/进程足够时间完成写入
- 大幅减少并发场景下的 `database is locked` 错误

**注意事项**:
- 启用 WAL 模式后，数据库会额外生成 `-wal` 和 `-shm` 文件
- 这些文件是 WAL 模式的正常产物，不应手动删除
- 当最后一个连接关闭时，WAL 文件会自动清理
