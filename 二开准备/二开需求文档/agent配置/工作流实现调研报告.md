# 工作流实现调研报告

> 调研目标：将 novel-master 的"模式2：写作章节"流程拆分为两个固定工作流，避免主 Agent 遗漏步骤

---

## 1. 现有架构分析

### 1.1 当前实现方式

```
novel-master (主 Agent)
    ↓ task 工具调用
    ├── novel-world-organizer (子 Agent)
    ├── novel-character-organizer (子 Agent)
    ├── novel-item-organizer (子 Agent)
    ├── novel-writer (子 Agent)
    ├── continuity-auditor (子 Agent)
    ├── novel-reviser (子 Agent)
    ├── chapter-summarizer (子 Agent)
    ├── state-settler (子 Agent)
    ├── hook-manager (子 Agent)
    └── card-manager (子 Agent)
```

**问题**：
- 主 Agent 通过 SOUL.md 提示词控制流程顺序
- LLM 决策存在不确定性，经常遗漏步骤
- 缺乏强制性的流程控制机制

### 1.2 现有代码架构

| 组件 | 文件 | 作用 |
|------|------|------|
| `make_lead_agent` | `agents/lead_agent/agent.py` | 创建主 Agent |
| `create_agent` | `langchain.agents` | LangChain 原生 Agent 创建 |
| `task_tool` | `tools/builtins/task_tool.py` | 子 Agent 调用工具 |
| `SubagentExecutor` | `subagents/executor.py` | 子 Agent 执行引擎 |
| `langgraph.json` | 根目录 | LangGraph 图定义 |

## 2. LangGraph 工作流支持情况

### 2.1 LangGraph 核心能力

LangGraph 是 LangChain 生态中专门用于构建**有状态、多步骤**工作流的框架。核心概念：

```python
from langgraph.graph import StateGraph

# 定义状态类型
class WorkflowState(TypedDict):
    chapter_num: int
    world_reference: str
    character_reference: str
    # ...

# 创建状态图
workflow = StateGraph(WorkflowState)

# 添加节点（每个节点是一个处理步骤）
workflow.add_node("organize_world", organize_world_func)
workflow.add_node("organize_characters", organize_characters_func)
workflow.add_node("write_chapter", write_chapter_func)
workflow.add_node("audit", audit_func)

# 添加边（定义执行顺序）
workflow.add_edge("organize_world", "organize_characters")
workflow.add_edge("organize_characters", "write_chapter")

# 添加条件边（支持分支逻辑）
workflow.add_conditional_edges(
    "audit",
    lambda state: "pass" if state["audit_passed"] else "fail",
    {
        "pass": "post_process",
        "fail": "revise"
    }
)

# 编译为可执行图
app = workflow.compile()
```

### 2.2 LangGraph 支持的工作流模式

| 模式 | 支持 | 说明 |
|------|------|------|
| **顺序执行** | ✅ | `add_edge(A, B)` |
| **并行执行** | ✅ | 多个节点同时执行 |
| **条件分支** | ✅ | `add_conditional_edges` |
| **循环/重试** | ✅ | 条件边指向前序节点 |
| **状态共享** | ✅ | `StateGraph` 状态在节点间传递 |
| **子图嵌套** | ✅ | 节点可以是另一个 `StateGraph` |
| **人工干预** | ✅ | `interrupt_before` / `interrupt_after` |
| **检查点/持久化** | ✅ | `checkpointer` 参数 |

### 2.3 DeerFlow 中的 LangGraph 使用

从 `langgraph.json` 可以看到：

```json
{
  "graphs": {
    "lead_agent": "deerflow.agents:make_lead_agent"
  }
}
```

DeerFlow 目前只使用了 **Agent 模式**（单个 `create_agent` 调用），没有使用 **Workflow 模式**（`StateGraph` 多节点编排）。

## 3. 实现方案分析

### 方案 A：纯提示词优化（不改架构）

**思路**：优化 SOUL.md，增加更详细的步骤说明和检查清单

**优点**：
- 改动最小，无需修改代码
- 风险最低

**缺点**：
- 无法根治 LLM 遗漏步骤的问题
- 依赖模型能力，不同模型表现不一致

**结论**：❌ 不推荐，无法解决根本问题

---

### 方案 B：LangGraph StateGraph 工作流（推荐）

**思路**：使用 LangGraph 的 `StateGraph` 构建固定工作流，将整理和写作流程编码为确定性图

**架构设计**：

```
novel-master (主 Agent)
    ↓ 用户指令
    ├── 判断任务类型
    │
    ├── [整理工作流] StateGraph
    │   ├── confirm_chapter (确认章节)
    │   ├── create_task_folder (创建任务文件夹)
    │   ├── organize_world (并行) ──┐
    │   ├── organize_characters (并行) ──┤
    │   ├── organize_items (并行) ──┘
    │   └── assemble_context (汇总)
    │
    ├── [写作工作流] StateGraph
    │   ├── write_chapter (写作)
    │   ├── audit (审核)
    │   ├── conditional:
    │   │   ├── pass → post_process
    │   │   └── fail → revise → audit (最多2次)
    │   ├── post_process (后处理)
    │   │   ├── summarize_chapter
    │   │   ├── settle_state
    │   │   ├── update_hooks
    │   │   └── update_card
    │   └── sync_outline (同步细纲)
    │
    └── 其他模式（新建/修改/规划/查看）
```

**优点**：
- 流程确定性执行，不会遗漏步骤
- 支持并行、条件分支、循环
- 与 LangGraph 生态完全兼容
- 可复用现有子 Agent 作为节点

**缺点**：
- 需要编写 Python 代码实现工作流
- 需要定义状态类型和节点函数
- 改动较大

**结论**：✅ 推荐，根本性解决问题

---

### 方案 C：混合方案（Agent + 工具链）

**思路**：将工作流封装为一个"超级工具"，主 Agent 调用该工具触发整个流程

**架构设计**：

```
novel-master (主 Agent)
    ↓ 调用工具
    └── execute_writing_workflow (Tool)
        ├── 内部按固定顺序调用子 Agent
        └── 返回执行结果
```

**优点**：
- 主 Agent 只需一次工具调用
- 工具内部保证流程顺序
- 改动相对较小

**缺点**：
- 工具内部逻辑复杂
- 不够灵活，难以处理异常
- 与 LangGraph 理念不太一致

**结论**：⚠️ 可选，但不如方案 B 优雅

## 4. 推荐方案详细设计（方案 B）

### 4.1 状态类型定义

```python
from typing import TypedDict, Annotated
from langgraph.graph import add_messages

class WritingWorkflowState(TypedDict):
    # 基本信息
    novel_name: str                    # 小说名称
    chapter_num: int                   # 当前章节号
    chapter_group: str                 # 章节组范围（如 "01-05"）
    
    # 整理阶段输出
    world_reference: str               # 世界观参考内容
    character_reference: str           # 人物参考内容
    item_reference: str                # 道具参考内容
    storyline_reference: str           # 故事线参考内容
    
    # 写作阶段
    writing_task_summary: str          # 写作任务汇总
    chapter_content: str               # 章节正文内容
    
    # 审核阶段
    audit_report: str                  # 审计报告
    audit_passed: bool                 # 审核是否通过
    audit_round: int                   # 审核轮次（最多2次）
    
    # 后处理阶段
    chapter_summary: str               # 章节摘要
    state_updated: bool                # 状态是否更新
    hooks_updated: bool                # 伏笔是否更新
    card_updated: bool                 # 名片是否更新
    outline_synced: bool               # 细纲是否同步
    
    # 错误处理
    error: str | None                  # 错误信息
```

### 4.2 整理工作流实现

```python
from langgraph.graph import StateGraph, END

def create_organize_workflow() -> StateGraph:
    """创建整理工作流"""
    workflow = StateGraph(WritingWorkflowState)
    
    # 添加节点
    workflow.add_node("confirm_chapter", confirm_chapter_node)
    workflow.add_node("create_task_folder", create_task_folder_node)
    workflow.add_node("organize_world", organize_world_node)
    workflow.add_node("organize_characters", organize_characters_node)
    workflow.add_node("organize_items", organize_items_node)
    workflow.add_node("organize_storyline", organize_storyline_node)
    workflow.add_node("assemble_context", assemble_context_node)
    
    # 定义执行顺序
    workflow.set_entry_point("confirm_chapter")
    workflow.add_edge("confirm_chapter", "create_task_folder")
    
    # 并行执行三个整理任务
    workflow.add_edge("create_task_folder", "organize_world")
    workflow.add_edge("create_task_folder", "organize_characters")
    workflow.add_edge("create_task_folder", "organize_items")
    workflow.add_edge("create_task_folder", "organize_storyline")
    
    # 汇总（等待所有并行任务完成）
    workflow.add_edge(["organize_world", "organize_characters", "organize_items", "organize_storyline"], "assemble_context")
    workflow.add_edge("assemble_context", END)
    
    return workflow.compile()
```

### 4.3 写作工作流实现

```python
def create_writing_workflow() -> StateGraph:
    """创建工作流"""
    workflow = StateGraph(WritingWorkflowState)
    
    # 添加节点
    workflow.add_node("write_chapter", write_chapter_node)
    workflow.add_node("audit", audit_node)
    workflow.add_node("revise", revise_node)
    workflow.add_node("post_process", post_process_node)
    workflow.add_node("sync_outline", sync_outline_node)
    
    # 定义执行顺序
    workflow.set_entry_point("write_chapter")
    workflow.add_edge("write_chapter", "audit")
    
    # 条件分支：审核结果
    workflow.add_conditional_edges(
        "audit",
        lambda state: "pass" if state["audit_passed"] else "fail",
        {
            "pass": "post_process",
            "fail": "revise"
        }
    )
    
    # 修改后重新审核（最多2次）
    workflow.add_conditional_edges(
        "revise",
        lambda state: "audit" if state["audit_round"] < 2 else "post_process",
        {
            "audit": "audit",
            "post_process": "post_process"
        }
    )
    
    # 后处理
    workflow.add_edge("post_process", "sync_outline")
    workflow.add_edge("sync_outline", END)
    
    return workflow.compile()
```

### 4.4 节点函数实现示例

```python
from langchain.agents import create_agent
from deerflow.subagents import get_subagent_config

def organize_world_node(state: WritingWorkflowState) -> dict:
    """整理世界观节点"""
    # 获取子 Agent 配置
    config = get_subagent_config("novel-world-organizer")
    
    # 创建子 Agent
    agent = create_agent(
        model=create_chat_model(config.model),
        tools=get_available_tools(config.tools),
        system_prompt=config.system_prompt,
    )
    
    # 构建任务提示
    task = f"""
    小说名称：{state['novel_name']}
    章节范围：第{state['chapter_group']}章
    
    请整理当前章节需要的世界观设定，输出到：
    book/{state['novel_name']}/02-正文/第{state['chapter_group']}章/_task/世界观参考.md
    """
    
    # 执行任务
    result = agent.invoke({"messages": [{"role": "user", "content": task}]})
    
    # 读取输出文件
    output_path = f"book/{state['novel_name']}/02-正文/第{state['chapter_group']}章/_task/世界观参考.md"
    world_reference = read_file(output_path)
    
    return {"world_reference": world_reference}
```

## 7. 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| LangGraph 版本兼容性 | 高 | 锁定 LangGraph 版本，充分测试 |
| 并行执行死锁 | 中 | 设置超时机制 |
| 子 Agent 调用失败 | 中 | 实现重试和降级策略 |
| 状态传递错误 | 中 | 严格类型检查和验证 |
| 性能问题 | 低 | 监控执行时间，优化热点 |

---

## 8. 结论

**推荐方案**：使用 LangGraph StateGraph 构建固定工作流（方案 B）

**核心优势**：
1. 流程确定性执行，不会遗漏步骤
2. 与 LangGraph 生态完全兼容
3. 支持并行、条件分支、循环等复杂流程
4. 可复用现有子 Agent 作为节点

**预期效果**：
- 主 Agent 不再需要记忆复杂流程
- 工作流自动保证步骤顺序
- 审核循环有明确的退出条件
- 并行整理提高效率
