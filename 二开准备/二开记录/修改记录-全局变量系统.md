## 一、需求背景

DeerFlow 项目需要在每次调用大模型时，**动态向系统提示词中注入可变的变量值**。

### 一期需求
1. **增删改查**：大模型可通过工具修改变量；外部业务脚本可通过 API 修改变量
2. **两级隔离**：项目级变量（所有对话共享）+ 对话级变量（单个对话独立）
3. **自动注入**：变量值自动全部注入到系统提示词中

### 二期需求
1. **模板替换**：不再自动注入，改为在 SOUL.md 等提示词模板中用 `{{变量名}}` 语法手动引用
2. **系统变量**：新增默认的系统变量（如 `workdir`），前端不可编辑、大模型不可修改
3. **llm_editable 权限**：每个变量可控制大模型是否能通过工具修改
4. **前端管理页面**：在系统设置中新增"全局变量"管理页面

### v2.1 存储优化
1. **SQLite 迁移**：从 JSON 文件存储迁移到 SQLite 数据库（`{DEER_FLOW_HOME}/global_variables.db`）
2. **字段隔离**：使用 UPDATE + INSERT 两段式写入，禁止 INSERT OR REPLACE
3. **懒加载**：新建对话无需手动创建文件，数据库自动处理

> 历史开发日志见 `全局变量更新.md`（已合并至本文档）

### 2.3 模板替换

**语法**：`{{变量名}}`

**示例**（SOUL.md）：
```markdown
当前工作目录：{{workdir}}
你是{{role}}，当前处理第{{chapter}}章。
```

**替换规则**：
1. 对话级变量覆盖项目级变量
2. 未匹配的 `{{变量名}}` 保持原样不替换
3. 替换发生在两处：
   - **加载时**：`get_agent_soul()` 读取 SOUL.md 后替换（项目级变量）
   - **运行时**：中间件在每次大模型调用前替换（含对话级变量）

### 2.3.1 运行时替换机制（v2.3 修复）

**问题背景**：

v2.0-v2.2 使用 `before_model` hook 替换模板变量，但发现 `{{novel_toc}}` 等对话级变量无法被替换。

**根本原因**：

通过阅读 langchain-agents 源码发现：
- `system_message` 存储在 `ModelRequest.system_message` 中（闭包变量）
- `before_model` hook 只能看到 `state["messages"]`，其中**不包含 SystemMessage**
- `SystemMessage` 仅在 `_execute_model_sync` 中才 prepend 到消息列表

```
# factory.py L1117-1126: model_node
request = ModelRequest(
    model=model,
    system_message=system_message,  # 存储在这里
    messages=state["messages"],     # 不包含 SystemMessage
)

# factory.py L1097-1099: _execute_model_sync
if request.system_message:
    messages = [request.system_message, *messages]  # 仅在此处 prepend
```

**修复方案**：

将 `before_model` hook 改为 `wrap_model_call` + `awrap_model_call` hook：

```python
def _apply_global_variables(request):
    """替换模板变量，返回修改后的 request。"""
    config = get_global_variables_config()
    if not config.enabled:
        return request

    system_msg = request.system_message
    if not system_msg:
        return request

    content = system_msg.content
    if not isinstance(content, str) or not content:
        return request

    thread_id = runtime.context.get("thread_id")
    updated = replace_template_variables(content, thread_id=thread_id)

    if updated != content:
        new_msg = SystemMessage(content=updated, id=system_msg.id, name=system_msg.name)
        request = request.override(system_message=new_msg)

    return request


class GlobalVariablesMiddleware(AgentMiddleware):
    @override
    def wrap_model_call(self, request, handler):
        return handler(_apply_global_variables(request))

    @override
    async def awrap_model_call(self, request, handler):
        return await handler(_apply_global_variables(request))
```

**关键点**：
- `wrap_model_call` 直接访问 `request.system_message`（而非 `state["messages"]`）
- 使用 `request.override(system_message=new_msg)` 创建新请求（不可变模式）
- 同时实现 `wrap_model_call`（同步）和 `awrap_model_call`（异步），否则异步调用会报错
- 中间件注册位置：`agent.py` 的 `_build_middlewares()`（生产环境）和 `factory.py` 的 `_assemble_from_features()`（SDK API）

**同步 vs 异步**：

langchain-agents 框架支持同步和异步两种调用模式。中间件必须同时实现两种版本：
- `wrap_model_call(self, request, handler)` → 同步版本
- `awrap_model_call(self, request, handler)` → 异步版本

如果只实现同步版本，异步调用（`astream()`/`ainvoke()`）会报错：
```
Asynchronous implementation of awrap_model_call is not available.
```

## 五、数据结构

### 数据库表结构

存储引擎已迁移至 SQLite 数据库（`{DEER_FLOW_HOME}/global_variables.db`）。

```sql
CREATE TABLE IF NOT EXISTS global_variables (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    thread_id TEXT NULL,
    key TEXT NOT NULL,
    value TEXT NOT NULL,
    description TEXT DEFAULT '',
    is_system BOOLEAN DEFAULT FALSE,
    llm_editable BOOLEAN DEFAULT TRUE,
    updated_at TEXT NOT NULL,
    updated_by TEXT NOT NULL,
    UNIQUE(thread_id, key)
);
```

**字段说明**：
- `thread_id IS NULL` → 项目级变量
- `thread_id = 'xxx'` → 对话级变量
- `is_system=True` → 系统变量（启动时自动同步，前端只读）

**详细表结构文档**：见 `数据库表结构-全局变量.md`

### 写入规范（字段隔离原则）

**禁止使用 `INSERT OR REPLACE`**：会完全替换整行记录，未指定字段被设为 NULL。

**使用 UPDATE + INSERT 两段式**：

```python
# 先 UPDATE
cursor.execute("""
    UPDATE global_variables
    SET value = ?, description = ?, llm_editable = ?, updated_at = ?, updated_by = ?
    WHERE thread_id IS NULL AND key = ?
""", (value, description, llm_editable, now, "api", key))

# 如果没更新到行，则 INSERT
if cursor.rowcount == 0:
    cursor.execute("""
        INSERT INTO global_variables
        (thread_id, key, value, description, is_system, llm_editable, updated_at, updated_by)
        VALUES (?, ?, ?, ?, ?, ?, ?, ?)
    """, (None, key, value, description, False, llm_editable, now, "api"))
```

**设计说明**：
- SQLite 不支持 MySQL 的 `ON DUPLICATE KEY UPDATE`
- 使用 `rowcount == 0` 判断是否需要 INSERT
- 只更新指定字段，不覆盖其他模块的数据

## 七、注意事项

1. **变量引用语法**：使用 `{{变量名}}`（双大括号），不是 `${变量名}`（美元符号）
2. **变量名**：系统变量名是 `workdir`（小写），不是 `__WORKING_DIR__`
3. **模板替换时机**：SOUL.md 加载时替换（项目级变量）+ 运行时中间件替换（含对话级变量）
4. **系统变量保护**：前端只显示锁定图标，API 返回 403 拒绝修改
5. **系统变量已同步到数据库**：启动时自动同步，其他模块可直接查询数据库

### 7.1 系统变量存储机制

**核心设计**：系统变量以代码中的 `SYSTEM_VARIABLES` 常量为权威来源，启动时自动同步到数据库。

```python
# storage.py 中的定义
SYSTEM_VARIABLES: dict[str, Any] = {
    "workdir": {
        "value": "/mnt/shared-data",
        "description": "Shared workspace directory",
        "is_system": True,
        "llm_editable": False,
        "updated_at": "system",
        "updated_by": "system",
    },
}
```

**工作流程**（v2.2 更新）：

| 阶段 | 操作 | 说明 |
|------|------|------|
| **启动** | `_init_database()` → `_sync_system_variables_to_db()` | 将系统变量写入数据库（UPDATE + INSERT） |
| **加载** | `load()` → `{**SYSTEM_VARIABLES, **db_variables}` | 从数据库读取，系统变量兜底合并 |
| **保存** | `save()` → `if var_data.get("is_system"): continue` | 跳过系统变量，不覆盖数据库中的同步值 |

**设计优势**：
- 系统变量持久化到数据库，其他模块可直接查询
- `SYSTEM_VARIABLES` 常量仍是权威来源，代码更新时自动同步
- 数据库中的值作为"快照"，方便外部脚本读取
- 前端无需修改，通过 API 自动获取

**验证方法**：
```bash
# 查看数据库内容（应包含系统变量）
sqlite3 ~/.deer-flow/global_variables.db "SELECT * FROM global_variables WHERE is_system = 1;"

# 调用 API 查看变量（应包含 workdir）
curl http://localhost:8080/api/global-variables/project
```

### 7.2 变量不存在时的显示行为

| 情况 | 提示词中显示 | 示例 |
|------|-------------|------|
| **变量不存在** | 保持原样 `{{变量名}}` | `当前章节：{{chapter}}` |
| **变量存在，值为空字符串** `""` | 显示空白 | `当前章节：` |
| **变量存在，但没设 value 字段** | 保持原样 `{{变量名}}` | `当前章节：{{chapter}}` |

**关键代码**（`prompt_injector.py`）：

```python
def _replacer(match):
    var_name = match.group(1)
    var_data = merged_vars.get(var_name)
    if var_data is None:
        return match.group(0)  # 变量不存在 → 保持原样 {{变量名}}
    if isinstance(var_data, dict):
        return str(var_data.get("value", match.group(0)))  # 没value字段 → 保持原样
    return str(var_data)
```

**总结**：
- 不会显示 `undefined` 或 `null`
- 变量不存在时保留原始占位符，方便排查问题
- 变量值为空字符串时显示空白

### 9.1 系统变量同步到数据库（✅ 已实现 v2.2）

**需求背景**：
系统变量（如 `workdir`）需要持久化到数据库，方便其他模块直接查询。

**实现方案**：
在 `_init_database()` 中添加 `_sync_system_variables_to_db()` 调用，每次数据库连接初始化时自动同步。

**核心代码**（`storage.py`）：

```python
def _sync_system_variables_to_db(self, conn: sqlite3.Connection) -> None:
    """Sync system variables to database on startup."""
    now = utc_now_iso_z()
    cursor = conn.cursor()
    for key, var_data in SYSTEM_VARIABLES.items():
        # UPDATE first
        cursor.execute("""
            UPDATE global_variables
            SET value = ?, description = ?, updated_at = ?, updated_by = ?
            WHERE thread_id IS NULL AND key = ?
        """, (var_data["value"], var_data["description"], now, "system", key))
        # INSERT if not exists
        if cursor.rowcount == 0:
            cursor.execute("""
                INSERT OR IGNORE INTO global_variables
                (thread_id, key, value, description, is_system, llm_editable, updated_at, updated_by)
                VALUES (?, ?, ?, ?, ?, ?, ?, ?)
            """, (None, key, var_data["value"], var_data["description"],
                  True, var_data["llm_editable"], now, "system"))
    conn.commit()
```

**设计要点**：
- 使用 UPDATE + INSERT 两段式（字段隔离原则）
- `INSERT OR IGNORE` 防止重复插入
- `SYSTEM_VARIABLES` 常量仍是权威来源，数据库值作为"快照"
- 其他模块可直接 `SELECT * FROM global_variables WHERE key = 'workdir'`
- 前端无需修改，通过 API 自动获取同步后的系统变量
- `is_custom` 计算排除系统变量，避免误判

**测试验证**：
