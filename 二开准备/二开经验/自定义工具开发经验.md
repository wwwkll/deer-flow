# 自定义工具开发经验

## 1. 沙箱路径 vs 主机路径

### 核心概念

DeerFlow 使用沙箱机制隔离文件系统访问。Agent 看到的路径是**沙箱虚拟路径**（如 `/mnt/shared-data/...`），而实际文件操作需要在**主机路径**（如 `E:\xiangmu\deer-flow-data\shared-data\...`）上执行。

### 路径映射配置

在 `config.yaml` 中配置沙箱挂载点：

```yaml
sandbox:
  use: deerflow.sandbox.local:LocalSandboxProvider
  allow_host_bash: false
  mounts:
    - host_path: E:\xiangmu\deer-flow-data\shared-data
      container_path: /mnt/shared-data
      read_only: false
```

### 常见问题

**问题**：工具调用返回成功，但文件/目录未实际创建。

**原因**：自定义工具直接使用 `os.makedirs()` 或 `open()` 操作路径，但没有将沙箱虚拟路径转换为主机路径。

**解决方案**：

```python
from my_tools.path_resolver import resolve_to_host_path

# 错误：直接操作 agent 传入的路径
os.makedirs(file_path, exist_ok=True)  # 可能在错误的位置创建

# 正确：先解析为主机路径
host_path = resolve_to_host_path(file_path)
os.makedirs(host_path, exist_ok=True)
```

## 2. 相对路径处理

### Agent 传入的路径格式

Agent 可能传入两种格式的路径：

1. **绝对路径**：`/mnt/shared-data/book/小说名`
2. **相对路径**：`book/小说名` 或 `./book/小说名`

### 处理建议

自定义工具应该同时支持两种格式：

```python
def _resolve_path(file_path: str) -> str:
    """解析路径：支持沙箱绝对路径、相对路径。"""
    normalized = file_path.replace("\\", "/").strip()
    if normalized.startswith("/"):
        # 绝对路径：直接转换
        return resolve_to_host_path(normalized)
    # 相对路径：去除 ./ 前缀，基于挂载点拼接
    relative = normalized.removeprefix("./")
    return resolve_to_host_path(f"/mnt/shared-data/{relative}")
```

### 注意事项

- Agent 的工作目录（workspace）和项目共享目录（shared-data）是两个不同的路径
- 相对路径应该基于项目共享目录解析，而不是 agent 的 workspace
- 在 SOUL.md 中建议指示 agent 使用绝对路径，减少歧义

## 3. 工具注册与配置

### 注册自定义工具

在 `config.yaml` 的 `tools` 段注册：

```yaml
tools:
  - name: master_writer
    group: master:write
    use: my_tools.master_writer:master_writer
```

### 配置 Agent 使用工具组

在 `agents/{agent_name}/config.yaml` 中配置：

```yaml
tool_groups:
  - file:read
  - master:write  # 包含 master_writer 工具
```

### 命名规范

- 工具组名使用冒号风格：`master:write`, `novel:tools`, `novel:reader`
- 工具名使用下划线风格：`master_writer`, `novel_reader`

## 4. 路径解析工具

### path_resolver.py

项目已提供统一的路径解析工具：

```python
from my_tools.path_resolver import resolve_to_host_path

# 将沙箱路径转换为主机路径
host_path = resolve_to_host_path("/mnt/shared-data/book/测试小说")
# 结果：E:\xiangmu\deer-flow-data\shared-data\book\测试小说
```

### 实现原理

`path_resolver.py` 读取 `config.yaml` 中的 `sandbox.mounts` 配置，建立容器路径到主机路径的映射关系，然后进行前缀替换。

## 5. 调试技巧

### 添加日志

在自定义工具中添加详细日志，方便排查路径问题：

```python
import logging
logger = logging.getLogger(__name__)

# 记录路径转换过程
logger.info("[tool_name] action=%s, input=%s, resolved=%s", action, file_path, host_path)

# 记录操作结果
exists = os.path.exists(host_path)
logger.info("[tool_name] create_dir: %s (exists=%s)", host_path, exists)
```

### 验证路径解析

编写测试脚本验证路径解析是否正确：

```python
from my_tools.path_resolver import resolve_to_host_path

test_paths = [
    "/mnt/shared-data/book/测试小说",
    "book/测试小说",
    "./book/测试小说",
]

for p in test_paths:
    print(f"{p} -> {resolve_to_host_path(p)}")
```

## 6. 最佳实践

1. **始终使用路径解析**：不要直接操作 agent 传入的路径，必须先解析为主机路径
2. **支持多种路径格式**：同时支持绝对路径和相对路径
3. **明确挂载点**：在文档和 SOUL.md 中明确告知 agent 应该使用的路径格式
4. **添加详细日志**：方便排查路径转换和操作是否成功
5. **测试验证**：编写测试脚本验证工具在各种路径格式下的行为

## 7. 示例：完整的自定义工具

```python
from langchain.tools import tool
import os
import logging
from my_tools.path_resolver import resolve_to_host_path

logger = logging.getLogger(__name__)


def _resolve_path(file_path: str) -> str:
    """解析路径：支持沙箱绝对路径、相对路径。"""
    normalized = file_path.replace("\\", "/").strip()
    if normalized.startswith("/"):
        return resolve_to_host_path(normalized)
    relative = normalized.removeprefix("./")
    return resolve_to_host_path(f"/mnt/shared-data/{relative}")


@tool("my_custom_tool", parse_docstring=True)
def my_custom_tool(
    description: str,
    file_path: str,
) -> str:
    """自定义工具示例。

    Args:
        description: 操作说明
        file_path: 目标路径（绝对路径如 /mnt/shared-data/...，或相对路径如 book/小说名）
    """
    host_path = _resolve_path(file_path)
    logger.info("[my_custom_tool] input=%s, resolved=%s", file_path, host_path)

    try:
        os.makedirs(host_path, exist_ok=True)
        exists = os.path.exists(host_path)
        return f"[OK] 目录已创建：{file_path} (host: {host_path}, exists: {exists})"
    except Exception as e:
        logger.error("[my_custom_tool] error: %s", e)
        return f"[FAIL] 操作失败：{str(e)}"
```
